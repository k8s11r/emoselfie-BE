# BE-3 · game-loop

**의존** BE-2 room
**요구사항** RD-01 ~ RD-10, EM-01 ~ EM-04, 7.2
**PRD** 5.3 라운드 진행 · 5.4 감정 세트 · DECISIONS C-1, C-5

---

## 목표

**서버가 시계를 쥔다.** 라운드를 열고, 절대 마감 시각을 정해 내려보내고, 마감이 되면 닫는다. 클라이언트 간 상태 전환 편차는 500ms 이내여야 한다.

---

## 규칙

### 라운드 구성

| ID | 규칙 |
|---|---|
| RD-01 | 기본 5라운드. 방장이 **3 / 5 / 7** 중 선택. |
| RD-02 | 라운드마다 감정 카드 1개를 전원에게 동시 공개. **같은 게임 내 감정 중복 없음.** |
| RD-03 | 감정 공개 후 3초 카운트다운, 이어서 기본 **20초** 촬영·제출 시간. |
| RD-04 | 제한시간은 방장이 **15 / 20 / 30초** 중 선택 (C-5, P1→P0 승격). |

7라운드 옵션이 성립하는 이유는 감정이 정확히 7종이기 때문이다 (C-1). 감정 세트를 줄이면 RD-01도 함께 손봐야 한다.

### 마감 시각 — 이 모듈의 핵심

| ID | 규칙 |
|---|---|
| RD-08 | **제한시간의 기준은 서버가 정한 마감 시각이다.** 서버가 절대 시각을 내려주고 클라이언트는 남은 시간을 표시만 한다. 클라이언트가 화면 로딩 시점부터 자체 카운트하지 않는다. |

```
round.startedAt     = now()
round.revealAt      = startedAt + 3s          # 카운트다운
round.deadlineAt    = revealAt + timeLimitSec
```

`round:revealed`에 `deadlineAt`을 ISO8601 UTC 절대 시각으로 싣는다. 상대 초(`remainingSec`)를 보내지 않는다. 네트워크 지연만큼 클라이언트마다 다른 시각에 끝나기 때문이다.

마감 처리는 Redis 기반 지연 작업으로 스케줄한다. Pod가 죽어도 다른 Pod가 이어받아야 하므로 `asyncio.sleep`으로 붙들지 않는다.

### 종료 조건

| ID | 규칙 |
|---|---|
| RD-07 | **전원 제출** 시 남은 시간과 무관하게 라운드를 종료하고 최종 정렬로 넘어간다. |
| RD-06 | 미제출자는 그 라운드 0점, 다른 참여자의 결과 화면에 "미제출"로 표시. 본인은 결과를 볼 수 없다 (RS-11). |
| RD-10 | **자발적 건너뛰기 수단을 제공하지 않고, 마감 시 자동 제출도 하지 않는다.** 촬영 버튼을 누르지 않았으면 캡처된 이미지 자체가 없다. |

자동 제출을 버린 이유는 두 가지다. 프리뷰 프레임을 몰래 잡아 올리는 것은 CP-03(정상 촬영 세션 토큰)과 어긋나고, 본인이 모르는 사이 얼굴이 올라가는 프라이버시 문제가 된다 (C-6).

라운드 종료 조건은 셋 중 먼저 오는 것:

```
1. deadlineAt 도달
2. 전원 제출 완료          (RD-07)
3. 참여자 2명 미만으로 감소  (PRD 10장)
```

### 제출 현황

| ID | 규칙 |
|---|---|
| RD-09 | 촬영 화면에 `제출 인원/참여 인원`을 실시간 표시. **대기 중인 사용자(`waiting_next_game`)는 분모에서 제외.** |

`submission:status`로 발행한다. 이 이벤트에는 **점수를 절대 넣지 않는다** (RS-09). 아직 제출하지 않은 사람이 남의 점수를 보면 목표 점수를 알고 표정을 조절할 수 있다.

### 감정 세트

엔진 표준 7종과 1:1. 표시 이름은 제품 톤의 별칭이며 **채점은 항상 엔진 라벨 기준**이다.

| 엔진 라벨 | 표시 이름 | 이모지 | 색 |
|---|---|---|---|
| `happy` | 기쁨 | 😆 | `#FFD72F` |
| `sad` | 슬픔 | 😢 | `#5AC8FF` |
| `angry` | 분노 | 😠 | `#FF5A47` |
| `surprise` | 놀람 | 😲 | `#8F66FF` |
| `neutral` | 시크 | 😐 | `#80EFD6` |
| `disgust` | 우웩 | 🤢 | `#B8F16A` |
| `fear` | 무서움 | 😨 | `#FF3D86` |

| ID | 규칙 | 우선순위 |
|---|---|---|
| EM-01 | 위 7종. 엔진이 지원하지 않는 감정은 세트에 넣을 수 없다. | P0 |
| EM-02 | 각 감정은 표시 이름·이모지·한 줄 설명을 갖는다. **서버가 라운드 공개 시 함께 내려준다.** | P0 |
| EM-03 | 난이도 높은 감정(우웩·무서움)이 연속 2회 이상 나오지 않게 한다. | P1 |
| EM-04 | 방장이 "쉬움(5종) / 전체(7종)" 선택. 쉬움은 우웩·무서움 제외. | P1 |

표시 이름·설명·색을 FE에 하드코딩하지 않는다. 서버가 `round:revealed`로 내려준다 (C-1). 문구를 고칠 때 FE 배포가 필요 없어야 한다.

`disgust`·`fear`의 한 줄 설명은 신규 작성 대상이다 (C-1). 예: 놀람 → "뒤에서 누가 부른 것처럼".

### 게임 시작·종료

| ID | 규칙 |
|---|---|
| RO-08 | 시작은 방장만. 대기실 인원 2명 이상일 때 활성화. |
| FN-01 | 모든 라운드 종료 시 최종 결과. 이 시점에 소유 슬롯 반환 (RO-13) → BE-2가 처리. |

판별 엔진 전체 장애 시: 해당 라운드를 무효 처리하고 재시도를 안내한다. **3회 연속 실패하면 게임을 중단하고 현재까지의 순위를 공개한다.** (PRD 10장)

## 데이터

```
Round
  id             UUID PK
  roomId         UUID FK→Room
  index          int              -- 1-based
  targetEmotion  text             -- 엔진 라벨 (happy | sad | ...)
  startedAt      timestamptz
  revealAt       timestamptz
  deadlineAt     timestamptz      -- 판정의 유일한 기준 (RD-08, CP-08)
  endedAt        timestamptz NULL
  status         enum(countdown|capturing|scoring|finalized|closed)
  -- UNIQUE(roomId, index)
  -- UNIQUE(roomId, targetEmotion)   ← RD-02 중복 금지를 DB로 강제
```

`UNIQUE(roomId, targetEmotion)`이 RD-02의 구현이다. 추첨 로직의 버그가 있어도 같은 감정이 두 번 나올 수 없다.

```
POST /api/rooms/{slug}/start     방장 · 2명 이상 → game:started
```

이벤트:

| 이벤트 | 방향 | 페이로드 |
|---|---|---|
| `game:started` | S→C | `{totalRounds, timeLimitSec}` |
| `round:revealed` | S→C | `{index, totalRounds, emotion: {label, displayName, emoji, hint, color}, revealAt, deadlineAt}` |

## 테스트

- `deadlineAt`이 절대 UTC 시각으로 내려간다. 상대 초가 없다
- `timeLimitSec` 15/20/30 각각 마감 시각이 맞다
- 허용값 밖(예: 3600) 거부
- 한 게임 7라운드에서 감정 7종이 모두 다르다
- DB 제약이 같은 방 같은 감정 두 번을 막는다
- 전원 제출 → 남은 시간 무관하게 즉시 종료 (RD-07)
- 마감 도달 → 미제출자 0점 처리
- `submission:status` 페이로드에 점수 필드가 없다 (RS-09)
- `waiting_next_game` 참여자가 분모에서 빠진다 (RD-09)
- 마감 스케줄을 등록한 Pod를 죽여도 다른 Pod가 마감시킨다
- `round:revealed`에 표시 이름·이모지·설명·색이 포함된다 (EM-02)
- 참여자 2명 미만 → 게임 종료 + 현재 순위
- inference 3회 연속 전체 장애 → 게임 중단 + 현재 순위

## 하지 않는 것

```
❌ 클라이언트에 상대 시간(remainingSec) 전달
❌ 클라이언트가 보낸 시각으로 라운드 종료 판정
❌ 자동 제출 / 건너뛰기 버튼 (RD-10)
❌ submission:status에 점수 포함 (RS-09)
❌ 감정 표시 이름·색을 FE 하드코딩에 맡김
❌ 마감 타이머를 단일 Pod의 asyncio.Task로만 유지
❌ 엔진 라벨에 없는 감정 추가 ("설렘", "당황" 등 — C-1에서 폐기)
```
