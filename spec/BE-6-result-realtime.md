# BE-6 · result-realtime

**의존** BE-5 submission
**요구사항** RS-01 ~ RS-15, RX-01 ~ RX-11, FN-01 ~ FN-03, 7.2
**PRD** 5.8 라운드 결과 · 5.9 리액션 · 5.10 최종 결과 · DECISIONS C-2, C-3, C-4, C-10

---

## 목표

결과를 **제출한 사람부터 개별로** 흘려보내고, **미제출자에게는 아무것도 보내지 않는다.** 리액션과 스킵을 집계하고, 마지막에 최종 순위를 낸다.

이 모듈이 잘못되면 미제출자가 결과를 보게 되거나(RS-12 위반), 전원 스킵이 영원히 성립하지 않아 게임이 멈춘다.

---

## 실시간 개별 발행

| ID | 규칙 |
|---|---|
| RS-01 | 제출을 마친 참여자는 남은 시간과 무관하게 **즉시** 결과 화면으로 전환된다. 미제출자는 촬영 화면에 머문다. |
| RS-04 | 제출 직후 판별 전까지는 "판별 중" 상태로 레일에 자리를 잡고, 점수가 확정되면 이동한다. 미제출자는 레일 끝에 대기 상태로 표시한다. |
| RS-05 | `N / N 채점 완료`를 표시한다. |
| RS-06 | 마감 시 미제출자를 0점으로 레일 맨 뒤에 추가한다. 사진이 없으므로 캐러셀 대상에서 제외한다. |
| RS-07 | 전원 결과가 확정되면 최종 정렬을 마치고 라운드 획득 포인트를 표시한다. |
| RS-09 | 아직 제출하지 않은 참여자에게 다른 사람의 점수를 노출하지 않는다. |

`submission:scored`를 **제출·채점될 때마다 1건씩** 발행한다 (C-3). 전원을 기다렸다 한꺼번에 보내지 않는다.

```
{ participantId, nickname, colorTag, imageUrl,
  status, targetScore, topEmotions,
  currentRank,        ← 표시용. 포인트를 확정하지 않는다 (SC-09)
  scoredCount, totalCount }
```

정렬 기준은 **감정 점수 내림차순** (RS-03). 순위 포인트가 아니다.

## 미제출자 차단 — 이 모듈에서 가장 틀리기 쉬운 부분

| ID | 규칙 |
|---|---|
| RS-11 | 제한시간 내 제출하지 못한 참여자는 그 라운드 결과를 볼 수 없다. 사진·점수·순위·리액션 어느 것도 노출하지 않고 대기 안내 화면으로 보낸다. |
| RS-12 | **차단은 클라이언트에서 가리는 방식이 아니라, 서버가 결과 관련 이벤트를 발행하지 않는 방식으로 구현한다.** |
| RS-13 | 페널티 대상은 **미제출자(`missed`)에 한한다.** 얼굴 미검출(SC-04)·판정 불가(SC-05)는 본인 책임이 아니므로 결과를 정상적으로 본다. |
| RS-14 | 페널티 화면에는 놓쳤다는 사실과 다음 라운드까지 남은 시간만 표시한다. |

미발행 대상:

```
submission:scored     round:finalized     reaction:updated
round:skipStatus      round:closed 의 상세
```

미제출자 전용:

```
round:missed  { nextRoundStartsAt }
```

### 구현 규칙

수신자 필터링을 **`realtime/emit.py` 한 곳에서만** 한다.

```python
async def emit_round_result(round_id, event, payload):
    """RS-12: missed 참여자를 수신자에서 제외한다."""
```

핸들러마다 `if participant.status != 'missed'`를 흩뿌리면 언젠가 한 군데가 빠진다. Socket.IO room을 결과 열람자용으로 분리하는 방법도 있다 — 라운드마다 `round:{id}:viewers` room을 만들고 제출·채점된 참여자만 join시킨다 (C-6).

이미지 서빙 엔드포인트(BE-5)도 같은 차단을 통과해야 한다. 이벤트만 막고 HTTP를 열어두면 URL 직접 접근으로 뚫린다.

최종 결과(FN-01)는 페널티 대상에게도 **정상적으로 보여준다.** 차단은 라운드 단위다.

## 리액션

**점수에 반영되지 않는 순수한 반응이다** (C-4).

| | ♥ 좋아요 | ⁇ 물음표 |
|---|---|---|
| 의미 | 공감·재미 | "띠용?" — 주제에 맞는 사진인지 의구심 |
| 향하는 대상 | 사진 | **엔진의 판정.** 사람이 아니다 |
| 점수 | 없음 | 없음 |

| ID | 규칙 |
|---|---|
| RX-01 | 두 종류 모두 **점수·순위에 영향을 주지 않는다.** |
| RX-02 | 각 리액션은 **사진 하나당 1회.** 여러 사진에 각각 행사할 수 있다. |
| RX-03 | 두 리액션은 독립. 같은 사진에 ♥와 ⁇를 함께 줄 수 있다. |
| RX-04 | **토글로 취소** 가능. |
| RX-05 | 자기 사진에는 어느 리액션도 불가. |
| RX-06 | 해당 사진이 도착해 채점이 끝나는 **즉시** 가능. 최종 정렬을 기다리지 않는다. |
| RX-07 | 미제출자는 행사할 수 없다. |
| RX-08 | 얼굴 미검출·판정 불가 사진도 **리액션 대상에 포함**한다. |
| RX-09 | 리액션 수를 실시간 표시. **누가 눌렀는지는 표시하지 않는다.** |
| RX-10 | 라운드 종료 시점에 확정하고 이후 변경을 반영하지 않는다. |
| RX-11 | 최종 화면에 참여자별 누적 ♥·⁇를 나란히 표시하고, 누적 ♥ 최다에게 **"가장 사랑받은 표정"** 을 시상한다. |

**`LK-01` ~ `LK-08`은 폐기됐다.** 라운드당 1표도, 5포인트 보너스도 없다.

RX-11은 P1에서 P0로 승격됐다. 리액션이 점수에서 빠지면서 "점수가 낮아도 웃긴 표정을 살려준다"는 원래 논리가 갈 곳을 잃었고, 이 시상이 유일한 귀결이 되었기 때문이다 (C-4).

`reaction:updated` 페이로드에 actor 정보를 넣지 않는다 (RX-09). 집계 수만 보낸다.

### 노출 시간 편향 (기록)

실시간 리액션이면 먼저 도착한 사진이 더 오래 노출되어 ♥를 더 받는다. 점수 반영이 없어 순위에는 영향이 없지만 "가장 사랑받은 표정"에는 유리하게 작용한다. **MVP에서 수용하고 베타에서 관찰한다.** 보정 로직을 넣지 않는다.

## 결과 감상 시간과 스킵

| ID | 규칙 |
|---|---|
| RS-08 | 최종 정렬 이후 감상 시간을 준다. **`min(60, 10 + 참여 인원 × 2)`초.** 방장은 즉시 넘길 수 있다. |
| RS-15 | **결과를 보는 참여자 전원이 스킵을 누르면 즉시 다음 라운드로.** 방장 전용이 아니고 토글로 취소 가능하다. **미제출자는 분모에서 제외한다.** |

| 인원 | 2 | 5 | 8 | 12 |
|---|---|---|---|---|
| 감상 시간 | 14초 | 20초 | 26초 | 34초 |

인원 비례인 이유: 캐러셀로 사진을 한 장씩 넘겨 보는데, 12명이면 12장이고 10초 고정으로는 장당 0.8초라 얼굴도 못 알아본다 (C-10).

미제출자를 분모에 넣으면 **전원 스킵이 영원히 성립하지 않는다.** 페널티 화면에는 결과가 없어 스킵 버튼도 없기 때문이다. 이것이 RS-15에서 가장 중요한 문장이다.

RD-07과 대칭이다.

```
RD-07   전원이 제출하면     → 남은 시간 무관하게 라운드 종료
RS-15   전원이 스킵을 누르면 → 남은 시간 무관하게 다음 라운드
```

부수 효과로, 방장 이탈 60초 유예 중(RO-10)에도 남은 사람들끼리 스킵으로 게임을 굴릴 수 있다.

다음 라운드 진행 조건 (먼저 오는 것):

```
1. 감상 시간 만료
2. 방장 스킵          (RS-08)
3. 결과 열람자 전원 스킵 (RS-15)
```

## 최종 결과

| ID | 규칙 |
|---|---|
| FN-01 | 모든 라운드 종료 시 1~3위 시상대 + 전체 순위표. **페널티를 받은 참여자에게도 정상 공개.** 이 시점에 방의 소유 슬롯이 반환된다 (RO-13). |
| FN-02 | 순위표에 누적 포인트와 참여자별 누적 리액션(♥ ⁇)을 함께 표시한다. **좋아요 보너스 내역은 없다.** |
| FN-03 | "새 방 만들기" / "나가기". **방장·참여자 구분 없이 누구나** 새 방을 만들 수 있다. |
| FN-04 | 최종 순위표 이미지 저장·공유 (P1). 버튼은 그리되 **비활성 + 비활성 이유 문구 동반** (C-11). |

**"다시하기"(구 FN-03)는 MVP에서 뺐다** (C-12). 같은 인원 재시작은 P2다.

`game:finished` 발행 시 BE-2에 소유 슬롯 반환을 요청한다. 이게 없으면 최종 화면의 "새 방 만들기"가 RO-03에 걸려 방금 끝난 방으로 튕긴다.

## 데이터

```
Reaction
  id                  UUID PK
  roundId             UUID FK→Round
  actorParticipantId  UUID FK→Participant
  targetSubmissionId  UUID FK→Submission
  type                enum(like|question)
  createdAt           timestamptz
  -- UNIQUE(targetSubmissionId, actorParticipantId, type)   ← RX-02·03
  -- 취소는 레코드 삭제 (RX-04)

RoundSkip
  roundId        UUID FK→Round
  participantId  UUID FK→Participant
  createdAt      timestamptz
  -- UNIQUE(roundId, participantId)
  -- 취소는 레코드 삭제 (RS-15)
```

유니크 키가 `(targetSubmissionId, actorParticipantId, type)`인 점에 주의한다. 가이드라인 §16의 `(roundId, voterParticipantId)`는 v0.6 시절 "라운드당 1표" 규칙의 잔재이며, **적용하면 RX-02를 위반한다.**

## 인터페이스

| 이벤트 | 방향 | 페이로드 | 미제출자 |
|---|---|---|---|
| `submission:scored` | S→C | 확정 결과 1건. 제출할 때마다 개별 발행 | ✕ |
| `round:finalized` | S→C | 최종 정렬, 순위 포인트, 감상 시간 마감 시각 | ✕ |
| `round:missed` | S→C | `{nextRoundStartsAt}` | **전용** |
| `reaction:sent` | C→S | `{targetSubmissionId, type}` 토글 | 거부 |
| `reaction:updated` | S→C | `{submissionId, likeCount, questionCount}` — actor 없음 | ✕ |
| `round:skip` | C→S | 토글 | 거부 |
| `round:skipStatus` | S→C | `{skipped, total}` — total은 결과 열람자 수 | ✕ |
| `round:closed` | S→C | 리액션 확정, 라운드 포인트 | △ 상세 제외 |
| `game:finished` | S→C | 최종 순위, 누적 리액션, `mostLiked` | ○ |

## 테스트

```
[개별 발행]
  1번 제출 → 1번만 submission:scored 수신, 나머지는 미수신
  3명 제출 → scored 3건이 순차 발행
  정렬 기준이 감정 점수 내림차순 (RS-03)
  currentRank 는 표시용, rankPoints 는 finalized 전 NULL (SC-09)
[차단 — 가장 중요]
  missed 참여자가 submission:scored 미수신
  missed 참여자가 round:finalized 미수신
  missed 참여자가 reaction:updated 미수신
  missed 참여자가 round:skipStatus 미수신
  missed 참여자만 round:missed 수신
  missed 참여자가 이미지 URL 직접 호출 → 거부
  no_face 참여자는 결과를 정상 수신 (RS-13)
  failed 참여자는 결과를 정상 수신 (RS-13)
  missed 참여자도 game:finished 는 수신 (FN-01)
[리액션]
  같은 사진에 ♥ 2회 → 두 번째는 토글 취소
  같은 사진에 ♥ + ⁇ 동시 → 둘 다 성립 (RX-03)
  서로 다른 사진 3장에 각각 ♥ → 3건 모두 성립 (RX-02)
  자기 사진 → 거부 (RX-05)
  채점 완료 즉시 가능, 최종 정렬 전 (RX-06)
  missed 참여자 → 거부 (RX-07)
  no_face·failed 사진에 리액션 가능 (RX-08)
  reaction:updated 에 actor 정보 없음 (RX-09)
  라운드 종료 후 리액션 → 무시 (RX-10)
  리액션 수가 totalPoints·rank 에 영향 없음 (RX-01, SC-06)
[스킵]
  결과 열람자 전원 스킵 → 즉시 다음 라운드 (RS-15)
  missed 1명 + 나머지 전원 스킵 → 진행됨 (분모 제외)
  스킵 토글 취소 → 카운트 감소
  방장 부재 상태에서 전원 스킵 → 진행됨
  방장 단독 스킵 → 즉시 진행 (RS-08)
[감상 시간]
  인원 2 → 14초, 5 → 20초, 12 → 34초, 30 → 60초 상한
[최종]
  game:finished 시 소유 슬롯 반환 → 즉시 새 방 생성 성공 (FN-01, C-12)
  mostLiked = 누적 ♥ 최다 (RX-11)
  순위표에 좋아요 보너스 항목 없음 (FN-02)
```

## 하지 않는 것

```
❌ 전원 대기 후 결과 일괄 공개 (C-3에서 폐기)
❌ 결과를 보낸 뒤 Client에서 가리기 (RS-12)
❌ 수신자 필터링을 핸들러마다 분산
❌ 미제출자를 스킵 분모에 포함 (게임이 멈춘다)
❌ 리액션을 점수·순위에 반영 (RX-01, SC-06)
❌ 라운드당 1표 제한 (LK-02 폐기)
❌ (roundId, voterParticipantId) 유니크 제약 (RX-02 위반)
❌ 리액션 actor 노출 (RX-09)
❌ 노출 시간 편향 보정 로직 (MVP 수용)
❌ 다시하기 / 같은 인원 재시작 (C-12, P2)
❌ 감상 시간 10초 고정 (C-10에서 인원 비례로 변경)
```
